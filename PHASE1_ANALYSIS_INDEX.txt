QUICK PROBLEM SUMMARY
================================================================================

WHAT'S BROKEN:
- 4 of 5 test PDFs fail Phase 1 quality checks
- Anti-bribery Policy: 11 empty bold markers, 1 word fusion, 39 spurious spaces
- Code of Conduct: 10 empty bold markers, 2 word fusions, 47 spurious spaces
- Academic PDF: 2 empty bold markers, 1 word fusion, 136 spurious spaces
- Mixed PDF: 4 empty bold markers, 118 spurious spaces
- Only Diligent Security Policy passes (10.0/10.0 score)

ROOT CAUSE:
Three independent layers create and filter spaces inconsistently:

  Layer 1: TJ Processing (text.rs:2668)
  → Creates space spans with inherited bold formatting
  
  Layer 2: Span Merging (text.rs:1401-1468)
  → Attempts to merge adjacent fragments
  
  Layer 3: Markdown Rendering (markdown.rs:242, 330-362)
  → Applies bold markers to space-only blocks after filtering
  → Creates empty bold markers like "** **"

PDF SPEC VIOLATION:
- Spec says "text strings are as long as possible"
- Current design treats spaces as CONTENT (wrong!)
- Should treat spaces as POSITIONING ARTIFACTS (correct)

================================================================================
SOLUTION SUMMARY
================================================================================

THREE FOCUSED CODE CHANGES:

Fix #1: Space Spans Never Bold (1 line)
File: src/extractors/text.rs, line 2741
Change: Set font_weight: FontWeight::Normal instead of inheriting
Why: Spaces are not content - should never inherit formatting

Fix #2: Remove Pre-Filtering (1 line deletion)
File: src/converters/markdown.rs, line 242
Change: Delete the whitespace filter line
Why: Filtering after formatting creates orphaned bold flags

Fix #3: Guard Bold Rendering (2 lines)
File: src/converters/markdown.rs, lines 334, 340
Change: Add whitespace check before applying bold markers
Why: Never render bold markers for whitespace-only content

TOTAL EFFORT:
