ROOT CAUSE: CRITICAL BUG IN text.rs LINE 1381
================================================================================

BUGGY CODE:
  let should_merge = same_line
      && (self.merging_config.severe_overlap_threshold_pt..3.0).contains(&gap)
      //                                                        ^^^ HARDCODED!
      && !large_gap_indicates_column;

IMPACT:
  - Adaptive threshold computed (e.g., 0.3pt for tight layouts)
  - BUT span merging uses hardcoded 3.0pt threshold
  - Spans with 0.5pt gaps don't merge → word fusions persist

EXAMPLE FROM BATCH OUTPUT:

  Current (BUGGY):
    "SUBTITLE A—OFFICE   SECRETARY OFAGRICULTURE"
                                     ^^^^^^^^^^^^^ Word fusion
  
  Expected (FIXED):
    "SUBTITLE A—OFFICE OF THE SECRETARY OF AGRICULTURE"

================================================================================
THE FIX (ONE LINE CHANGE)
================================================================================

Replace line 1381 in src/extractors/text.rs:

FROM:
  let should_merge = same_line
      && (self.merging_config.severe_overlap_threshold_pt..3.0).contains(&gap)
      && !large_gap_indicates_column;

TO:
  let max_merge_gap = if self.merging_config.use_adaptive_threshold {
      self.merging_config.conservative_threshold_pt.max(3.0)
  } else {
      3.0
  };
  let should_merge = same_line
      && (self.merging_config.severe_overlap_threshold_pt..max_merge_gap).contains(&gap)
      && !large_gap_indicates_column;
