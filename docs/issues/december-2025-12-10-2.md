**Impact**: Fragments words into broken pieces; loses semantic meaning
**Prevalence**: 6,168+ lines with hyphen-terminated lines

#### Affected Categories:
- Government documents: 5,249 hyphenated line breaks

- Technical papers: 38 hyphens

#### Examples:

**Government CFR Documents**:

**Technical/RFC Documents**:
```

✅ SHOULD BE: "content-coding = token"
```

**Impact Assessment**:
- Hyphenated compound words become unrecognizable
- Dictionary/vocabulary matching fails (e.g., "Govern-ISBN" not in any lexicon)
- Reading order detection becomes confused
- Violates TJ operator word spacing semantics (Section 9.4.4)

**Root Cause**: Line break detection not considering hyphenation as continuation indicator

## Root Cause Analysis

### Common Underlying Issues

#### 1. Text Positioning Operator Handling
**PDF Spec Section 9.4.4 (Text Positioning)**

Current Implementation:
```rust
// In text extraction, using basic position tracking:
let x_pos = current_x;
let text_chunk = extract_text(obj);
// No consideration of word spacing or gaps
```

Problem:
- Td (position) and TJ (show text with offsets) operators not fully analyzed
- Word boundary detection relies on character-by-character positioning
- Gap analysis for inter-word spacing missing

**Fix Required**:
- Track spacing metrics from Tc (character spacing), Tw (word spacing), Tz (horizontal scaling)
- Analyze TJ offset values to identify word boundaries
- Apply geometric positioning rules per PDF spec

#### 2. Font Mapping Issues
**Phase 6 CMap Support Incomplete**

Current Status:
- ✅ CJK fonts (GB1, CNS1, Japan1, Korea1) supported
- ✅ 4-byte character codes working
- ❌ Font glyph-to-Unicode mapping for Western fonts incomplete
- ❌ Embedded vs predefined CMap fallback logic not optimal

**Fix Required**:
- Better validation of character mapping chains
- Fallback to font metrics when CMap unavailable
- Symbol font (ZapfDingbats, etc.) special handling

#### 3. Line Breaking and Hyphenation
**PDF Spec Section 9.4.2 (Text State Parameters)**

Current Issue:
- Lines ending with hyphen treated as normal line break
- No context awareness for word continuation
- Ligatures not properly expanded

**Fix Required**:
- Implement hyphenation dictionary lookup
- Track soft-hyphen (U+00AD) vs hard-hyphen differently
- Use ActualText (working in Phase 2) to resolve ligatures

#### 4. Whitespace Normalization
**PDF Spec Section 5.3 (Text Operators)**

Current Issue:
- Multiple consecutive spaces preserved as-is
- Tab characters (U+0009) not converted to spaces
- Leading/trailing spaces in text objects not trimmed

**Fix Required**:
- Implement post-extraction whitespace normalization
- Collapse multiple spaces to single space
- Track original spacing only for formatting preservation

#### 5. Layout Analysis for Word Boundaries
**Not Currently Implemented**

Missing Features:
- Multi-column layout detection
- Text flow direction analysis
- Table structure preservation
- Reading order determination

**Enhancement Required**:
- Add SpatialTableDetector integration
- Implement column-aware text assembly
- Track geometric bounding boxes for context
